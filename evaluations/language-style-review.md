# 1.0.0 语言风格校准

本轮按用户确认，以既有结构为基线，只补充句内及段内的语言编辑要求。目标是消除机械重复、过强断言和不顺畅的表达，字数增减不作为成功指标。已有示例与私人测试笔记未重排，也未批量改写。

## 编辑判断与对照

以下为仓库自编的最小样本，使用假设任务及数据，不是外部模型的原始生成结果。每行前后均为一个文本单元，编辑不引入换段或模块变更；后两行用于防止把所有确定语气和重复术语都当成问题。

| 检查点 | 待判断文本 | 处理结果与理由 |
| --- | --- | --- |
| 固定句式与空泛收尾 | 需要注意的是，检查先读取规则。需要注意的是，随后检查输入。这一点非常重要。 | 检查先读取规则，再检查输入。去掉重复起句和未补充信息的收尾，保留操作次序。 |
| 无依据的普遍保证 | 只要检查通过，所有文档就一定没有任何问题。 | 检查通过表示未发现检测范围内的问题，内容准确性仍需复核。限定检查能够支持的结论，而非在原保证前添加“可能”。 |
| 引用范围被扩大 | 假设来源只报告三份样本通过，正文却写：这证明所有输入都能通过。 | 这三份样本通过了检查，尚不能据此判断其他输入。保留样本数量和证据范围，不替假设来源编造其他结果。 |
| 多层修饰导致拖沓 | 对于在规则未改变的前提下由同一份输入产生的需要互相比较的两次检查结果，需要做的是确认它们的检查范围也相同。 | 比较同一份输入的两次检查结果时，除了确认规则未变，还需要确认检查范围相同。保留比较对象与两个条件，只调整语序。 |
| 断裂短句 | 检查完成了。输入没有变化。规则也没有变化。这两次结果可以继续比较。 | 检查完成后，输入和规则都未变化，因此可以继续比较这两次结果。只连接原句已经给出的关系，不增设新保证。 |
| 确定结论应保留 | 两个记录加上另外两个记录，共四个记录。 | 保留。可直接核对的算术结论无需弱化为“可能有四个”。 |
| 术语重复应保留 | 规则定义检查条件，检查结果记录规则是否满足。 | 保留。重复“规则”与“检查”有明确指代作用，机械换同义词反而可能造成歧义。 |

## 采用范围与验收边界

Humanizer 提供重复套式、空泛拔高与改写保真的编辑提示，但其中重组段落、改变标题或格式的做法不纳入本轮。[1][2] Google 的过度主张指南用于校准证据与断言的关系；其语气指南用于识别生硬、冗长及连续重复句首。[3][4] 这些来源主要面向英文，迁移到中文时按句子的实际作用判断，不照搬英文禁词表或句长标准。

本轮核对上述样本的事实、条件、数量和文本单元是否保留，并检查“不改也正确”的情况。自动化只核对现有 schema、回归样本、CLI 与数值示例等；不证明模型能自动识别这些语义问题。未运行独立模型盲测，也未将文风检测分数当作读者舒适度证据。
