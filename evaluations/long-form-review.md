# 长篇写作修订与验收记录

本轮针对用户提供的 Self-Attention 失败稿修复长文指导与验收缺口。此前仅用小型技术交接输出判断“使用测试通过”，证据范围不足；该结论撤回。失败稿已能触发旧检查器的警告，因此根因不只是缺少检测规则，还包括没有代表性长文示例、没有把警告落实到修订，以及把读取规范和局部测试当成写作质量证明。

## 观察依据与改动范围

对照的私人参考长文按少量大主题组织，章内用完整段落解释，再以真实子主题、并列项、比较表和必要步骤承载不同关系。本轮迁移这种组织方法，没有复制私人正文、目录或领域事实。原始失败稿和私人参考都不进入公开仓库；公开反例是围绕相同失败模式新编的最小输入。

| 可复核观察 | 失败稿 | 本轮修订例 | 说明 |
| --- | --- | --- | --- |
| 二级标题 | 55 | 6 | 只是本次结果，不是章节配额 |
| 三级标题 | 3 | 5 | 恢复计算和约束内部的父子主题 |
| fenced code block | 135 | 1 | 仅保留真正可运行程序，不用代码框强调变量 |
| 显示公式块 | 144 | 2 | 保留核心汇聚与多头关系，其余短数学量回正文 |
| 检查器 ERROR / WARNING | 0 / 79 | 0 / 0 | 无 ERROR 从来不能证明失败稿合格 |

数字按源文件块标记统计，不是浏览器像素测量。旧稿原始空行比例甚至低于私人参考，说明空行比例不能衡量无效留白；要检查标题、公式、代码和碎段是否反复打断同一解释。修订例不以篇幅下降作为验收依据，也不宣称将 55 节原文逐句无损保留。

## 同一内容怎样修复

[块级碎片反例](../examples/bad/block-fragmentation.md)把查询、键和分数分别升成二级标题，再把名称单独围成代码块。删除其空行仍然不能恢复机制，正确修复需要把三个概念放回一条解释：查询和键分别提供用于匹配的特征，点积给出每对位置的分数，缩放后的分数沿键方向归一化，权重再用于汇聚值。这段话保持因果联系，真实的数值推导才值得另行展示。

[修订例第二章](../examples/good/self-attention.md#二qkv-与一行输出的形成)进一步将来源、投影、维度、归一化方向和手算放在同一大主题内。形状表比较同一计算中的对象；短等式留在正文；核心公式独立展示后立即说明成立条件；数值例子始终使用同一组输入。这样读者不必在“Attention Matrix”“维度”“信息方向”等分散章节之间自行拼接计算。

| 原稿内容组 | 修订位置或处理 | 防止压缩造成的损失 |
| --- | --- | --- |
| 输入、Q/K/V、分数、缩放、softmax、值、维度和方向 | 第一、二章合并解释 | 保留符号定义、形状、方差假设和具体数值 |
| 位置、因果及填充掩码、训练并行 | 第三章按两种职责分组 | 保留访问集合、输入目标错位和全屏蔽行边界 |
| 多头、输出投影、残差、前馈、Self/Cross | 第四章整体解释 | 保留维度配置和分类轴，避免把注意力等同整层 |
| 最小实现与理解验证 | 第五章一个可运行例子 | 用完整数值、因果版本和异常输入核对实际计算 |
| 成本、长上下文、加速 | 第六章限定实现条件 | 区分二次计算、物化矩阵存储与分块精确注意力 |
| 多次总流程、概念表、心智模型与结尾复述 | 合并到首次解释处 | 删除重复表达，不删除第一次出现的关键关系 |
| KV Cache 细节、卷积/RNN 专题比较、多头完整工程代码 | 明确不在本修订例范围 | 这些是后续专题；不能声称本例替代所有进阶教程 |

## 技术核对与自动化证据

修订时对照原始 Transformer 论文及 FlashAttention 论文，链接保留在示例中。重点纠正无条件表述：全序列访问须限定双向情形；严格正权重须限定有限未屏蔽分数的实数 softmax；缩放方差解释须带独立、零均值和单位方差假设；二次矩阵存储须限定显式物化实现。原稿中部分结论在后文已有例外，因此这里记录为条件分散和解释缺口，不笼统宣称所有公式错误。

| 验证动作 | 实际结果 | 证据边界 |
| --- | --- | --- |
| `python3 scripts/validate.py --schema` | 19 条规则通过，schema 仍为 1 | 结构契约与示例双向映射 |
| `python3 scripts/validate.py --test` | 37 个既有 fixture 及维护检查通过 | 人工语义 fixture 只核对记录，不自动证明语义 |
| `python3 -m unittest discover -s tests -p 'test_*.py'` | CLI 与示例执行测试通过 | 运行发布在 Markdown 中的真实代码 |
| 原始失败稿 `--strict` 检查 | 退出 1；0 ERROR、79 WARNING | 明确阻止把该输入当成无待办的交付 |
| 修订长文 `--strict` 检查 | 退出 0；0 ERROR、0 WARNING | 仅检测范围内无发现 |

CLI 回归覆盖警告、渲染错误、无发现、JSON 兼容和文件不存在的情况。代码测试独立核对手算输出、修改 V 后的汇聚结果、全屏蔽行拒绝和大分数的稳定归一化；前后两个位置同值的简单演示不足以替代这些检验。检查器保留原来的默认退出码和 JSON 数组接口，新增显式 `BLOCKED`、`REVIEW_REQUIRED`、`STATIC_CLEAN` 状态；语义状态始终为 `NOT_EVALUATED`。

## 本轮人工审读与结论边界

本轮由修订作者审读，未冒充独立外部评审：术语在首次使用处解释；计算方向能从表格与例子相互核对；连续解释没有再被单变量块切碎；章节内保留可定位子问题；实数、掩码及实现条件就在相关结论附近；省去的专题在范围中明确说明。示例代码已执行，数学与结构按源 Markdown 审读，未声称完成各网页客户端的截图验收。

这证明仓库已提供可检查的长文目标形态和本次修订证据，不证明任意模型已经稳定迁移。修订后的无记忆网页会话、跨主题迁移和短问答防退化测试尚未实际运行，入口与失败判据见 [USAGE.md](../USAGE.md)。新生成结果须保留原稿逐项复核，不得再次把读文件记录或作者自编示例的成功提升为“所有场景已验证”。
