# 文档维护项目：当前决策

当前优先解决文档状态不一致的问题，暂不扩展为任务管理平台。已有说明能解释项目目标，却不能稳定区分已确认行为与正在讨论的建议；因此下一阶段只建立一份可复用的当前状态。每次更新应能回答什么仍然有效、什么已经改变，以及哪些问题还没有决定，而不是累积全部讨论过程。

## 当前范围与判断

| 方向 | 状态 | 当前判断 |
| --- | --- | --- |
| 规则登记 | 继续维护 | 保存稳定约束及其来源 |
| 当前状态摘要 | 小范围试用 | 验证是否减少重复确认 |
| 独立管理界面 | 暂不进入范围 | 当前没有足够证据支持维护成本 |

### 规则登记

规则登记负责让同一要求只有一个当前定义，正文则解释为什么需要这项要求以及如何使用它。两者分工后，阅读者可以先理解原则，检测器可以按稳定编号报告具体问题。登记表不收纳每次讨论的完整过程，也不把未确认建议包装成正式规则。

- **当前能力：** 检查必要字段与编号，关联正反样本，让修改能够追踪到具体约束。
- **下一阶段：** 用真实文档验证规则是否足够明确；只有出现新的独立概念时才考虑增加规则。
- **边界：** 检测通过只证明受支持的检查项满足要求，语义质量仍需人工阅读。

### 当前状态摘要

状态摘要回答“现在应该依据什么继续工作”。它只携带当前目标、已确认决策、进行中的工作和待决定事项；旧讨论被吸收到更新后的定义中，不保留成一串聊天摘要。如果两个来源矛盾，先标明矛盾及各自依据，等待确认后再更新，不能自行混成第三种方案。

处理结果采用四种有限状态，下面编号仅用于完整枚举，不表示执行顺序：

1. `KEEP`：当前定义仍有效，无需改动。
2. `UPDATE`：已有定义需要根据新确认信息修改。
3. `REVIEW`：来源冲突或证据不足，需要复核。
4. `RETIRE`：旧定义退出当前范围，保留退出原因。

## 下一步与验收

先选一份已经有人接手的文档，检查摘要能否支持接手者继续执行。重点是能否区分事实与提案、找到有效约束，并解释下一步为什么成立；不能仅以字段齐全作为成功依据。若摘要只是重复原文，应缩小内容或改善引用，不追加更多栏目。
