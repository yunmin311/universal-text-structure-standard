# 参考来源与公开样本

本规范由真实长期写作样本及用户明确确认的格式政策归纳，公开工程只保存选择后的脱敏摘录、改编教学资产与最小回归案例。不保存私人原始材料、私人笔记全文、个性化指令快照或本机路径；本地分析材料放入被忽略的 `.local-sources/`，CI 和测试不依赖该目录。

<a id="confirmed-policy"></a>
## 当前确认政策与合并记录

0.2.0 以本轮用户明确确认的格式政策为最高优先级，覆盖 0.1.0 的旧默认字段行为。正文完整解释条件与模式，规则登记仍保留原有 19 个编号；输出范围、语气与长期交接要求属于正文执行契约，不为每句话新增机器规则。原始确认文本仅在本地分析资料中保存，公开的 STANDARD.md 是经过分类、合并和扩写的规范，不是私人指令原文快照。

| 确认内容 | 归入现有定义 | 扩写重点 |
| --- | --- | --- |
| prose-first、两种模式、完整段落 | SEM-001、PRE-001、PRE-002 | 默认经验与硬约束分开，避免碎段和文字墙两个极端 |
| 并列、步骤、状态、长列表 | SEM-002、SEM-003、SEM-004 | 三项提示、六项复核不变成机械数量 gate |
| 标题、字段与嵌套 | SEM-005、SEM-006、PRE-004 | 独立导航价值、完整信息单元和真实从属 |
| 流程、树、精确内容 | SEM-007、PRE-005 | 普通短关系不强制代码块；布局需要才保留格式 |
| 留白与复杂文档 | PRE-003 及正文组织契约 | 保留语义分组，补齐技术机制、证据、复用与排错 |
| 文件名字段 | REN-004、REN-005 | 默认单独 inline code，合法嵌套仅例外 |
| 格式与渲染检查 | 既有三层规则 | 自动、启发式和人工检查分工；不冒充完整 parser |

新增解释均来自本轮明确确认内容；未把“2–5 段 / 3–6 句”和减少留白比例变成 validator 阈值。机器覆盖测试只核对关键内容锚点存在，完整性与语义仍需审读。与旧材料的已知差异按新确认处理，不把未确认推论加入 active。

## Gold Reference 与教学样本

每份示例顶部的 `rules` comment 与登记表双向对应，`provenance` 说明身份。Gold Reference 是特定结构行为的依据，不意味着每一个字都不可修改，也不意味着其他文档必须复制它的目录。

- `examples/good/project-inbox.md`：从真实项目记录的介绍段、并列属性、状态总览和有限枚举结构改编；替换私人项目、决策和具体事实，是脱敏 Gold Reference adaptation，不是原文全文。
- `examples/good/workflow.md`：保留真实长流程与文件归属样本的结构关系，以文档校验的中性主题重写，是脱敏 Gold Reference adaptation；其中步骤和父子列表用于解释关系选择。
- `examples/good/technical-handoff.md`：依据本仓库职责编写的完整教学样本，展示机制、修改、验证方法、复用和边界；不是声称来自未提供的真实历史报告。
- `examples/good/compact.md`：简短字段与表格示例，保留作为局部语法参考，不作为长篇 Gold Reference 计数。

<a id="regression"></a>
## 回归案例与历史边界

`project-inbox-regression.md` 保留从真实材料发现的“代码包住强调标记，冒号另外加粗”的组合，文件名为中性示例，职责正文缩减为通用描述。修正样本默认只使用 inline code，另有合法嵌套样本证明 WARNING 不等于语法 ERROR。其他 bad examples 是最小反例；人工样本明确标注待判断规则，不伪称检测器可以识别全部语义。
